## 3.2 DeVET集成功能

Bounty通过5个专用工具调用DeVET的REST API:

1. `devet_health` — 检查DeVET后端状态
2. `devet_build_scenario` — 构建3智能体Trading DAO委托链
3. `devet_verify_chain` — 验证链完整性(7步递归检查)
4. `devet_list_attacks` — 列出8种攻击类型
5. `devet_simulate_attack` — 模拟攻击+显示检测结果和归因

**验证流程**:
```
用户: "帮我验证这个委托链是否安全"
Bounty → devet_build_scenario → 构建链
Bounty → devet_verify_chain → 7步递归验证
Bounty: "✅ 验证通过，3个智能体全部可信"
```

**P4-1 自动验签（2026-08-13，与上版差异）**：上版是"用户显式调用 5 个 devet_* 工具"的手动流程；P4-1 起，每次 task/fleet 子代理完成后**无需用户干预**自动镜像验签：

```
用户: "用 task 派一个子代理调研 README 首行"
Bounty → task 子代理运行（3 次工具调用）
Bounty → POST /chain/mirror（身份+结果承诺+工具计数）
Bounty → POST /chain/verify（7 项递归检查）
子代理摘要尾部自动附加:
【DeVET 验证】
- 状态：✅ 真实有效（7 项递归检查全部通过）
- 承诺：sha256:xxxx…（子代理结论哈希，防伪造锚定）
Web「🛡️ 验证链」面板同步显示链与逐节点 ✓/✗
```

篡改演示（蓝队视角）：`/chain/tamper` 替换任一子证明后复验，返回 `authentic=false、fault_type=subagent_proof_invalid、blame_path=delegation[1] → SubAgentB`，责任精确归因到被伪造的委托节点。
